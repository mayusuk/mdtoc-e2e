# Plan: mdtoc v1

**Status:** Draft
**Base:** `origin/main @ 086fc6d`
**Tracking issue:** —

## Goal

`mdtoc` implements every requirement in `specs/SPEC.md` (FR-1 to FR-4): a Go library that extracts headings, makes GitHub-compatible slugs and renders a TOC, and a `mdtoc` command that prints it or updates it in place. This repository is also the end-to-end sandbox for agent-loop, so each task is sized to be one agent-implemented, agent-reviewed pull request.

## Context

- The repository has a skeleton only: `go.mod` (Go 1.25), `doc.go` (package `mdtoc`), a placeholder `cmd/mdtoc/main.go`, and CI (`.github/workflows/ci.yml`, job `ci`: gofmt, vet, build, `go test -race`). `main` requires the `ci` check.
- Sources read: `specs/SPEC.md`, `CLAUDE.md`, `.wf.toml`. No open issues.
- Rules: standard library only; tests named after requirements (`TestFR2AC3_...`).

## Approach

Four files in package `mdtoc` at the repository root, one per requirement, plus the command:

- `headings.go` (FR-1): a line scanner that tracks fenced code blocks and recognises ATX and setext headings.
- `slug.go` (FR-2): `Slug` and a `Slugger` that keeps a count per slug for uniqueness.
- `render.go` (FR-3): `Options`, inline-Markdown stripping, and the list renderer, which runs every heading through one `Slugger` so skipped levels still reserve slugs.
- `cmd/mdtoc/main.go` (FR-4): flag parsing, stdin/file input, `--in-place` and `--check` between the `<!-- toc -->` markers.

FR-1 and FR-2 don't depend on each other, so T1 and T2 can run in parallel. T3 needs both; T4 needs T3.

## Decisions

- **D1** [ambiguity] FR-2 AC2: `_` is removed as an emphasis marker only when it opens or closes a run at a word boundary (`_word_`); an underscore inside a word (`snake_case`) is kept, as GitHub keeps it. Why: AC1 keeps `_` as a slug character, so a blanket removal would contradict it.
- **D2** [gap] FR-2, FR-3 AC3: a heading's slug is made from its text after FR-3 AC3 stripping (links reduced to their text), then FR-2 AC1. Why: GitHub's anchors come from the rendered text, so `[a](b)` must slug as `a`.
- **D3** [gap] FR-4 AC3: marker lines inside a fenced code block are not markers, and a second `<!-- toc -->` pair is an error. Why: the spec doesn't say; this keeps `--in-place` from editing code samples.

## Out of scope

- CommonMark edge cases not named in the spec (HTML headings, headings in block quotes or lists, link reference definitions).
- Releases and packaging.

## Risks and open questions

- The work is done by agent-loop's handlers, not by `work-issue`. Any trouble there is a finding about agent-loop, not a reason to change this plan.

## Tasks

### T1: Extract ATX and setext headings (`headings.go`)

Add `type Heading struct { Level int; Text string; Line int }` and `func Headings(src []byte) []Heading` in `headings.go`, implementing FR-1 AC1–AC5. Tests in `headings_test.go`.

**Depends on:** —

**Acceptance criteria:**
- FR-1 AC1: ATX headings with level, trimmed text and closing `#` sequence removed, in document order, with 1-based line numbers.
- FR-1 AC2: setext level 1 and level 2 headings.
- FR-1 AC3: nothing inside backtick or tilde fences is a heading, including fences longer than three characters.
- FR-1 AC4: indented lines, `#hashtag` and seven-`#` lines are not headings.
- FR-1 AC5: inline Markdown is kept in `Text`.
- Each AC has a test named `TestFR1AC<n>_...`; CI passes.

### T2: Generate unique slugs (`slug.go`)

Add `func Slug(text string) string` and `type Slugger` with `Slug(text string) string` in `slug.go`, implementing FR-2 AC1–AC4 and D1. Tests in `slug_test.go`.

**Depends on:** —

**Acceptance criteria:**
- FR-2 AC1: the spec's examples (`Hello, World!` → `hello-world`, `Go 1.25 notes` → `go-125-notes`) and a non-ASCII case.
- FR-2 AC2: backticks and paired emphasis are removed with their content kept; `snake_case` keeps its underscore (D1).
- FR-2 AC3: `intro`, `intro-1`, `intro-2`, and a literal `intro-1` heading after a generated one gets a new unique slug.
- FR-2 AC4: punctuation-only text gives `section`, made unique.
- Each AC has a test named `TestFR2AC<n>_...`; CI passes.

### T3: Render the TOC (`render.go`)

Add `type Options` and `func Render(hs []Heading, opt Options) string` in `render.go`, implementing FR-3 AC1–AC5 and D2, using `Slugger` from T2 and `Heading` from T1. Tests in `render_test.go`.

**Depends on:** T1, T2

**Acceptance criteria:**
- FR-3 AC1: indentation relative to the shallowest level in range; trailing newline; empty input gives `""`.
- FR-3 AC2: out-of-range headings are skipped but still reserve slugs.
- FR-3 AC3: link text strips backticks, emphasis and links; slugs use the stripped text (D2).
- FR-3 AC4: `Ordered` numbers each nesting level from 1.
- FR-3 AC5: invalid ranges return `""`.
- Each AC has a test named `TestFR3AC<n>_...`; CI passes.

### T4: Build the `mdtoc` command (`cmd/mdtoc`)

Replace the placeholder in `cmd/mdtoc/main.go` with the command in FR-4 AC1–AC5 and D3, using `Headings` and `Render`. Keep `main` thin: put the logic in a `run(args []string, stdin io.Reader, stdout, stderr io.Writer) int` so it can be tested in `cmd/mdtoc/main_test.go` without building a binary.

**Depends on:** T3

**Acceptance criteria:**
- FR-4 AC1: file, `-` and stdin input.
- FR-4 AC2: `--min`, `--max` and `--ordered` reach `Render`.
- FR-4 AC3: `--in-place` replaces between markers, keeps them, ignores headings inside them, doesn't rewrite an unchanged file, and errors without markers or with markers in a code fence only (D3).
- FR-4 AC4: errors are prefixed `mdtoc: ` and exit 1; success exits 0; an invalid `--min`/`--max` range is an error.
- FR-4 AC5: `--check` exits 1 with `mdtoc: TOC is out of date` when stale, 0 when current, and never writes.
- Each AC has a test named `TestFR4AC<n>_...`; CI passes.
